## 没用还是有用

在学习一种程序设计语言的时候，
我们通常有两种张力很强、相互拉扯的焦虑，
如何用这门语言做点什么有用的东西，
一直在学用这门语言做没用的东西。
所以那个《XXX in Action》系列的书籍才会有卖得那么好……
可是，那个书里依然都是一些有用的没用东西。
到底是有用的没用东西，还是没用的有用东西呢？
实际上，有用的东西多半没用，而没用的东西多半很有用。

    有无相生，
    难易相成。

还有一个就是有用的东西很难学，而没用的东西很容易学。
最出奇的事情，有些时候，难学的东西居然很没用，而容易学的东西却很有用。

所以，说一千道一万，我们还是先从没用的东西开始学吧。

## 没用的有用项目

先来看一个例子，我想做一个非常有用的项目。

### 从 API_BASE 拉取随机 checklist

随机显示一个 checklist，里面的每一项都是一个 step，用户可以点击 checkbox 来完成每一项。每一项的 checkbox 只能在前一项完成后才能解锁。

<script>
  const API_BASE = 'https://sun-wukong.cn';
  const RANDOM_CHECKLIST_URL = `${API_BASE}/api/checklists/random`;

  function renderChecklist(checklist) {
    const container = document.getElementById('random-list-container');
    const items = Array.isArray(checklist?.items) ? checklist.items : [];

    function updateChecklistState() {
      const allCheckboxes = Array.from(container.querySelectorAll('input[type="checkbox"]'));

      let currentEnabledIndex = -1;
      for (let i = 0; i < allCheckboxes.length; i += 1) {
        if (!allCheckboxes[i].checked) {
          currentEnabledIndex = i;
          break;
        }
      }

      allCheckboxes.forEach((checkbox, index) => {
        const isChecked = checkbox.checked;
        const shouldEnable = isChecked || currentEnabledIndex === index || currentEnabledIndex === -1;

        checkbox.disabled = !shouldEnable;
        checkbox.style.cursor = shouldEnable ? 'pointer' : 'not-allowed';
        checkbox.style.opacity = shouldEnable ? '1' : '0.5';

        const label = checkbox.parentElement?.querySelector('label');
        if (label) {
          label.style.color = shouldEnable ? '#111827' : '#9ca3af';
        }
      });
    }

    const card = document.createElement('div');
    card.style.border = '1px solid #d1d5db';
    card.style.borderRadius = '0.75rem';
    card.style.padding = '1rem 1.25rem';
    card.style.background = '#f9fafb';
    card.style.marginTop = '0.75rem';

    const title = document.createElement('div');
    title.textContent = checklist?.title || '随机 checklist';
    title.style.fontWeight = '700';
    title.style.color = '#111827';
    title.style.fontSize = '1.05rem';
    title.style.marginBottom = '0.35rem';

    const description = document.createElement('div');
    description.textContent = checklist?.description || '暂无说明';
    description.style.color = '#374151';
    description.style.marginBottom = '0.75rem';
    description.style.lineHeight = '1.6';

    const list = document.createElement('ul');
    list.style.listStyle = 'none';
    list.style.paddingLeft = '0';
    list.style.margin = '0';

    items.forEach((item, index) => {
      const li = document.createElement('li');
      li.style.marginBottom = '0.5rem';

      const checkbox = document.createElement('input');
      checkbox.type = 'checkbox';
      checkbox.id = `check-${index}`;
      checkbox.dataset.index = String(index);
      checkbox.style.marginRight = '0.5rem';

      checkbox.addEventListener('change', function () {
        const currentIndex = Number(this.dataset.index);

        if (!this.checked) {
          for (let i = currentIndex + 1; i < items.length; i += 1) {
            const laterCheckbox = document.getElementById(`check-${i}`);
            if (laterCheckbox) {
              laterCheckbox.checked = false;
            }
          }
        }

        updateChecklistState();
      });

      const label = document.createElement('label');
      label.htmlFor = checkbox.id;
      label.textContent = typeof item === 'string' ? item : (item?.step ?? JSON.stringify(item));

      li.appendChild(checkbox);
      li.appendChild(label);
      list.appendChild(li);
    });

    card.appendChild(title);
    card.appendChild(description);
    card.appendChild(list);
    container.innerHTML = '';
    container.appendChild(card);
    updateChecklistState();
  }

  async function fetchRandomChecklist() {
    const container = document.getElementById('random-list-container');
    container.innerHTML = '<p>正在从 API_BASE 拉取随机 checklist...</p>';

    try {
      const res = await fetch(RANDOM_CHECKLIST_URL, {
        method: 'GET',
        headers: { Accept: 'application/json' }
      });

      if (!res.ok) {
        throw new Error(`HTTP ${res.status}`);
      }

      const payload = await res.json();
      if (!payload || !Array.isArray(payload.items) || payload.items.length === 0) {
        throw new Error('随机接口返回的 checklist 没有 items');
      }

      renderChecklist(payload);
    } catch (err) {
      container.innerHTML = `
        <p>拉取随机 checklist 失败。</p>
        <p>请检查接口是否真的存在：<code>${RANDOM_CHECKLIST_URL}</code></p>
        <p>也可以直接查看 <a href="${API_BASE}/api/docs" target="_blank" rel="noopener noreferrer">OpenAPI 文档</a>。</p>
      `;
    }
  }

  document.getElementById('random-list-btn').addEventListener('click', fetchRandomChecklist);
</script>

随机一个checklist的接口是 <code>/api/checklists/random</code>，返回值是一个 checklist 对象，里面的 <code>items</code> 是数组，每一项的字段是 <code>step</code>。

## 架构和代码

### 架构
在实现一个信息化系统的初期，
我们总是会优先采用比较简单的技术来实现一系列松耦合的必要组件，
然后再把这些必不可少的组件组合起来，
形成一个功能上完整的系统。
至于这个系统的性能，
后面如果这个系统还能拿到钱的话，
再逐一替换就行。


对于我们的 checklist 管理器来说，我们可以把它拆分为三个组件：

- 采用sqlite数据库来存储checklist数据
- 提供一个RESTful API来访问这些数据
- 提供一个网页（HTML/CSS/Javascript）来访问这些数据

大概上来说，就是这样几个层次，四个部分。

![Server-Browser架构](/rust/rfe/sb.png)

在实际的实现中，前两个部分被整合在一起，形成一个完整的服务端程序，提供RESTful API。
后两个部分甚至被放在一个文件中（非常不好的做法），形成一个完整的前端网页，提供用户界面。

### Checklist-core

首先是 checklist-core 的代码，主要是提供`ChecklistItem`和`Checklist`两个结构体，以及它们的序列化和反序列化方法。通过serde库，我们可以很方便地将它们序列化为JSON格式，或者从JSON格式反序列化回来。当然，我们为了方便，也提供了从文本格式（类似Markdown的格式）来创建Checklist的功能。

```rust
/**
 * A single checklist step persisted as a row in the `checklist_items` table.
 */
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct ChecklistItem {
    #[serde(default)]
    pub id: i64,
    pub step: String,
    #[serde(skip_serializing, skip_deserializing, default = "default_ip")]
    pub created_by_ip: String,
}

impl ChecklistItem {
    /// Creates a new checklist step with the caller-supplied creator IP for auditability.
    pub fn new(step: impl Into<String>, created_by_ip: impl Into<String>) -> Self {
        Self {
            id: 0,
            step: step.into(),
            created_by_ip: created_by_ip.into(),
        }
    }
}

/**
 * A complete checklist, including metadata and all step entries.
 *
 * A checklist can be created from API payloads, imported from text, or serialized for
 * export and import flows.
 */
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct Checklist {
    #[serde(default)]
    pub id: i64,
    pub title: String,
    pub description: String,
    pub created_at: DateTime<Utc>,
    #[serde(default)]
    pub items: Vec<ChecklistItem>,
    #[serde(skip_serializing, skip_deserializing, default = "default_ip")]
    pub created_by_ip: String,
    #[serde(default, skip_serializing, skip_deserializing)]
    pub source_id: Option<i64>,
}

impl Checklist {
    /// Creates a new checklist from a title, description, and raw item list.
    pub fn new(
        title: impl Into<String>,
        description: impl Into<String>,
        items: Vec<String>,
        created_by_ip: impl Into<String>,
    ) -> Self {
        let created_by_ip = created_by_ip.into();
        Self {
            id: 0,
            title: title.into(),
            description: description.into(),
            created_at: Utc::now(),
            items: items
                .into_iter()
                .map(|step| ChecklistItem::new(step, created_by_ip.clone()))
                .collect(),
            created_by_ip,
            source_id: None,
        }
    }

    /// Serializes the checklist into pretty-printed JSON for export or API use.
    pub fn to_json(&self) -> Result<String> {
        Ok(serde_json::to_string_pretty(self)?)
    }

    /// Parses a checklist from JSON produced by `to_json()` or another compatible payload.
    pub fn from_json(input: &str) -> Result<Self> {
        Ok(serde_json::from_str::<Checklist>(input)?)
    }

    pub fn to_packed_string(&self) -> Result<String> {
        let json = self.to_json()?;
        Ok(BASE64.encode(json.as_bytes()))
    }

    pub fn from_packed_string(input: &str) -> Result<Self> {
        let decoded = BASE64.decode(input)?;
        let json = String::from_utf8(decoded)?;
        Self::from_json(&json)
    }

    pub fn from_text(input: &str) -> Result<Self> {
        let mut lines = input.lines();
        let header = lines
            .next()
            .ok_or_else(|| ChecklistError::InvalidInput("missing checklist header".to_string()))?
            .trim();

        if !header.starts_with('#') {
            return Err(ChecklistError::InvalidInput(
                "header must start with '# '".to_string(),
            ));
        }

        let header = header.trim_start_matches('#').trim();
        let (title, description) = match header.split_once(':') {
            Some((title, description)) => (title.trim(), description.trim()),
            None => (header.trim(), ""),
        };

        if title.is_empty() {
            return Err(ChecklistError::InvalidInput(
                "title must not be empty".to_string(),
            ));
        }

        let items = lines
            .filter_map(|line| {
                let line = line.trim();
                if line.is_empty() {
                    None
                } else {
                    Some(line.to_string())
                }
            })
            .collect::<Vec<_>>();

        Ok(Self::new(title, description, items, "0.0.0.0"))
    }

    pub fn to_text(&self) -> String {
        let description = if self.description.trim().is_empty() {
            String::new()
        } else {
            format!(":{}", self.description)
        };

        let mut out = format!("# {}{}\n", self.title, description);
        for item in &self.items {
            out.push_str(&item.step);
            out.push('\n');
        }
        out
    }
}
```

然后是一个非常Naive的Sqlite数据库访问层，提供了对checklist的增删改查操作。

```rust
/**
 * SQLite-backed persistence layer for checklists and their steps.
 *
 * All reads and writes are centralized here to keep the application logic testable and
 * consistent across API routes.
 */
pub struct ChecklistStore {
    conn: Connection,
    database_path: String,
}

impl ChecklistStore {
    /// Opens or creates the SQLite database and initializes the required schema.
    pub fn open<P: AsRef<Path>>(path: P) -> Result<Self> {
        let database_path = path.as_ref().to_string_lossy().to_string();
        let conn = Connection::open(path)?;
        let store = Self {
            conn,
            database_path,
        };
        store.initialize()?;
        Ok(store)
    }

    pub fn database_path(&self) -> &str {
        &self.database_path
    }

    fn initialize(&self) -> Result<()> {
        self.conn.execute_batch(
            "
            CREATE TABLE IF NOT EXISTS checklists (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                title TEXT NOT NULL,
                description TEXT NOT NULL,
                created_at TEXT NOT NULL,
                created_by_ip TEXT NOT NULL,
                source_id INTEGER
            );

            CREATE TABLE IF NOT EXISTS checklist_items (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                checklist_id INTEGER NOT NULL,
                step TEXT NOT NULL,
                created_by_ip TEXT NOT NULL,
                FOREIGN KEY(checklist_id) REFERENCES checklists(id)
            );
            ",
        )?;
        Ok(())
    }

    pub fn create_checklist(&self, mut checklist: Checklist) -> Result<Checklist> {
        if checklist.title.trim().is_empty() {
            return Err(ChecklistError::InvalidInput(
                "title must not be empty".to_string(),
            ));
        }

        let created_at = checklist.created_at.to_rfc3339();
        let created_by_ip = checklist.created_by_ip.clone();

        self.conn.execute(
            "INSERT INTO checklists (title, description, created_at, created_by_ip, source_id) VALUES (?1, ?2, ?3, ?4, ?5)",
            params![
                checklist.title,
                checklist.description,
                created_at,
                created_by_ip,
                checklist.source_id,
            ],
        )?;

        let checklist_id = self.conn.last_insert_rowid();
        checklist.id = checklist_id;

        for item in &mut checklist.items {
            self.conn.execute(
                "INSERT INTO checklist_items (checklist_id, step, created_by_ip) VALUES (?1, ?2, ?3)",
                params![checklist_id, item.step, item.created_by_ip.clone()],
            )?;
            item.id = self.conn.last_insert_rowid();
        }

        Ok(checklist)
    }

    /// Returns the newest checklists ordered by creation time.
    pub fn list_checklists(&self) -> Result<Vec<Checklist>> {
        self.list_checklists_limited(None)
    }

    /// Returns a capped subset of the newest checklists. The cap is intentionally enforced
    /// here so the API layer and the UI share a consistent upper bound.
    pub fn list_checklists_limited(&self, limit: Option<usize>) -> Result<Vec<Checklist>> {
        let limit = limit
            .unwrap_or(DEFAULT_RESULT_LIMIT)
            .min(DEFAULT_RESULT_LIMIT);
        let mut stmt = self.conn.prepare(
            "SELECT id, title, description, created_at, created_by_ip, source_id FROM checklists ORDER BY created_at DESC LIMIT ?1",
        )?;

        let rows = stmt.query_map([limit as i64], |row| {
            Ok((
                row.get::<_, i64>(0)?,
                row.get::<_, String>(1)?,
                row.get::<_, String>(2)?,
                row.get::<_, String>(3)?,
                row.get::<_, String>(4)?,
                row.get::<_, Option<i64>>(5)?,
            ))
        })?;

        let mut checklists = Vec::new();
        for row in rows {
            let (id, title, description, created_at, created_by_ip, source_id) = row?;
            let created_at = DateTime::parse_from_rfc3339(&created_at)
                .map_err(|err| ChecklistError::InvalidInput(err.to_string()))?
                .with_timezone(&Utc);

            let items = self.load_items_for_checklist(id)?;
            checklists.push(Checklist {
                id,
                title,
                description,
                created_at,
                items,
                created_by_ip,
                source_id,
            });
        }

        Ok(checklists)
    }

    pub fn get_checklist(&self, id: i64) -> Result<Option<Checklist>> {
        let mut stmt = self.conn.prepare(
            "SELECT title, description, created_at, created_by_ip, source_id FROM checklists WHERE id = ?1",
        )?;

        let row = stmt
            .query_row([id], |row| {
                Ok((
                    row.get::<_, String>(0)?,
                    row.get::<_, String>(1)?,
                    row.get::<_, String>(2)?,
                    row.get::<_, String>(3)?,
                    row.get::<_, Option<i64>>(4)?,
                ))
            })
            .optional()?;

        let Some((title, description, created_at, created_by_ip, source_id)) = row else {
            return Ok(None);
        };

        let created_at = DateTime::parse_from_rfc3339(&created_at)
            .map_err(|err| ChecklistError::InvalidInput(err.to_string()))?
            .with_timezone(&Utc);

        let items = self.load_items_for_checklist(id)?;

        Ok(Some(Checklist {
            id,
            title,
            description,
            created_at,
            items,
            created_by_ip,
            source_id,
        }))
    }

    pub fn create_new_version_from(
        &self,
        source_id: i64,
        checklist: Checklist,
    ) -> Result<Checklist> {
        if self.get_checklist(source_id)?.is_none() {
            return Err(ChecklistError::NotFound(source_id));
        }

        let mut version = checklist;
        version.source_id = Some(source_id);
        self.create_checklist(version)
    }

    /// Searches over checklist titles, descriptions, and item text.
    pub fn search_by_term(&self, term: &str) -> Result<Vec<Checklist>> {
        self.search_by_term_limited(term, None)
    }

    /// Searches with a safe server-side cap to keep result payloads predictable.
    pub fn search_by_term_limited(
        &self,
        term: &str,
        limit: Option<usize>,
    ) -> Result<Vec<Checklist>> {
        let limit = limit
            .unwrap_or(DEFAULT_RESULT_LIMIT)
            .min(DEFAULT_RESULT_LIMIT);
        let needle = format!("%{}%", term.trim());
        let mut stmt = self.conn.prepare(
            "SELECT c.id, c.title, c.description, c.created_at, c.created_by_ip, c.source_id
             FROM checklists c
             LEFT JOIN checklist_items i ON i.checklist_id = c.id
             WHERE c.title LIKE ?1 OR c.description LIKE ?1 OR i.step LIKE ?1
             GROUP BY c.id
             ORDER BY c.created_at DESC
             LIMIT ?2",
        )?;

        let rows = stmt.query_map(params![&needle, limit as i64], |row| {
            Ok((
                row.get::<_, i64>(0)?,
                row.get::<_, String>(1)?,
                row.get::<_, String>(2)?,
                row.get::<_, String>(3)?,
                row.get::<_, String>(4)?,
                row.get::<_, Option<i64>>(5)?,
            ))
        })?;

        let mut results = Vec::new();
        for row in rows {
            let (id, title, description, created_at, created_by_ip, source_id) = row?;
            let created_at = DateTime::parse_from_rfc3339(&created_at)
                .map_err(|err| ChecklistError::InvalidInput(err.to_string()))?
                .with_timezone(&Utc);
            let items = self.load_items_for_checklist(id)?;
            results.push(Checklist {
                id,
                title,
                description,
                created_at,
                items,
                created_by_ip,
                source_id,
            });
        }

        Ok(results)
    }

    pub fn random_checklist(&self) -> Result<Option<Checklist>> {
        let row = self
            .conn
            .query_row(
                "SELECT id FROM checklists ORDER BY RANDOM() LIMIT 1",
                [],
                |row| row.get::<_, i64>(0),
            )
            .optional()?;

        match row {
            Some(id) => self.get_checklist(id),
            None => Ok(None),
        }
    }

    pub fn delete_checklist(&self, id: i64) -> Result<()> {
        self.conn
            .execute("DELETE FROM checklist_items WHERE checklist_id = ?1", [id])?;
        self.conn
            .execute("DELETE FROM checklists WHERE id = ?1", [id])?;
        Ok(())
    }

    fn load_items_for_checklist(&self, checklist_id: i64) -> Result<Vec<ChecklistItem>> {
        let mut stmt = self.conn.prepare(
            "SELECT id, step, created_by_ip FROM checklist_items WHERE checklist_id = ?1 ORDER BY id ASC",
        )?;

        let rows = stmt.query_map([checklist_id], |row| {
            Ok((
                row.get::<_, i64>(0)?,
                row.get::<_, String>(1)?,
                row.get::<_, String>(2)?,
            ))
        })?;

        let mut items = Vec::new();
        for row in rows {
            let (id, step, created_by_ip) = row?;
            items.push(ChecklistItem {
                id,
                step,
                created_by_ip,
            });
        }

        Ok(items)
    }
}
```

### checklist-server

这个服务器的代码就过于简单，用axum来实现，主要的代码量都在描述RESTful API的OpenAPI文档上了。

```rust
fn app(state: AppState) -> Router {
    let cors = CorsLayer::new()
        .allow_origin(Any)
        .allow_methods([Method::GET, Method::POST, Method::DELETE, Method::OPTIONS])
        .allow_headers(Any);

    Router::new()
        .route(
            "/api/checklists",
            get(list_checklists).post(create_checklist_handler),
        )
        .route("/api/checklists/search", get(search_checklists_handler))
        .route("/api/checklists/random", get(random_checklist_handler))
        .route(
            "/api/checklists/{id}",
            get(get_checklist_handler).delete(delete_checklist_handler),
        )
        .route(
            "/api/checklists/{id}/export.json",
            get(export_checklist_handler),
        )
        .route("/api/checklists/template", get(template_checklist_handler))
        .route(
            "/api/checklists/from-text",
            post(create_checklist_from_text_handler),
        )
        .route("/api/checklists/import", post(import_checklist_handler))
        .route("/api/checklists/pack", post(pack_checklist_handler))
        .route("/api/checklists/unpack", post(unpack_checklist_handler))
        .with_state(state)
        .layer(cors)

}
```

这个就是主要的API路由了，其他的就是一些辅助函数和错误处理。

主函数被标记为`#[tokio::main]`，使用tokio运行时来运行异步的axum服务器。

```rust
async fn main() {
```

### checklist-ui

这个网页的代码就更简单了，主要是一个HTML文件，里面包含了一些CSS和JavaScript代码，用来渲染checklist的界面。当然我们同样用一个`tokio`的服务器来提供这个网页。

```rust
#[derive(Clone)]
struct AppState {
    api_base: String,
}

fn ui_html(api_base: &str) -> String {
    let safe_api_base = api_base.replace('\\', "\\\\").replace('"', "\\\"");
    include_str!("../static/index.html")
        .replace("__API_BASE__", &safe_api_base)
}

async fn index(State(state): State<AppState>) -> Html<String> {
    Html(ui_html(&state.api_base))
}

#[tokio::main]
async fn main() {
    let cli = Cli::parse();
    let state = AppState {
        api_base: cli.api_base,
    };

    let app = Router::new()
        .route("/", get(index))
        .layer(TraceLayer::new_for_http())
        .with_state(state);

    let addr: SocketAddr = cli.bind.parse().expect("invalid bind address");
    println!("Checklist UI listening on http://{}", addr);
    let listener = tokio::net::TcpListener::bind(addr)
        .await
        .expect("failed to bind UI port");
    axum::serve(listener, app).await.expect("UI server failed");
}
```

我们的网页服务器跟checklist服务器是分开的，网页服务器只提供一个HTML文件，里面包含了JavaScript代码来访问checklist服务器的API。

### 运行与配置
这两个单可执行的文件就能够运行整个系统，在实际运行中，可以通过命令行参数来指定checklist服务器的API地址和网页服务器的绑定地址。



从这里看，rust中的`clap`库是非常方便的，可以很容易地定义命令行参数和选项。
实际运行中，需要确保防火墙开放两个端口，一个是checklist服务器的端口，另一个是网页服务器的端口。

```shell
checklist-server --database ./checklists.db --bind 0.0.0.0:8092
checklist-ui --api-base http://xxxx.xxxx.xxxx.xxxx:8092 --bind 0.0.0.0:8090
```

实际上，前端和后端之间的联系是非常简单的，前端只需要知道后端的API地址，就可以通过HTTP请求来访问checklist的数据。具体的API接口和返回的数据格式，可以通过访问`/api/docs`来查看OpenAPI文档。
